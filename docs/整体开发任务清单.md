# 整体开发任务清单

目标汇报时间：2026-11-20 左右。以 11 月 18 日前形成稳定本机演示版本为规划目标，11 月 19—20 日预留彩排与缓冲。日期为推进计划，完成情况按验证证据更新。

用户每周约 10 小时，主要负责集中决策、资料和人工验收；AI 辅助主要技术实现。本清单不把未发生的组员贡献或人工验收写成已完成。

## 最小范围与验收

- 本机启动，管理员与普通成员通过真实账号登录，身份不能由请求参数伪造。
- 项目成员只能访问所属项目；项目管理员管理本项目成员和资料，无全局隐式越权。
- 注册后申请加入团队，由团队管理员审批；只有已确认教师可创建团队，学生不可创建。团队公共资料与项目内部资料分别授权，退出团队撤销其下项目授权。
- 文本型 PDF 和 Markdown 上传后异步解析、分块和向量化，界面能查看任务状态。
- 授权范围内执行关键词与向量混合检索，支持重排序；只使用当前可用文档版本。
- 问答有引用和可查看的原文位置；证据不足及模型异常有明确反馈。
- 新版本完成后生效，失败保留旧版；撤下资料及撤销成员关系后受限内容不可访问。
- 请求有追踪标识，评测有真实配置及原始结果。
- PPT 与原型一致，实际人工贡献及 AI 参与有记录。

当前支持本机自助注册、教师/学生身份、教师确认及团队审批；教师创建限制与项目内部授权分开判断。不做找回密码、OCR、复杂多轮记忆、公网部署及大规模微服务。邮箱未验证，教师由本机可信管理员人工核实；真实资料外发须获得用户授权，开发自动验证先使用合成样例。

## 批次安排

1. **基础批次**：真实 PostgreSQL 迁移、登录会话、项目权限、登录与项目界面，自动安全回归。
2. **入库批次**：上传、文档版本、独立 Worker、任务状态和原文定位。
3. **问答批次**：混合检索、重排序、引用回答和前端完整闭环。
4. **可靠性批次**：版本和权限变化、失败恢复、追踪和回归。
5. **评测与汇报批次**：真实标注、实验、人工验收、演示及课程材料。

## 人工参与节点

- 基础批次完成：实际登录、切换项目，确认角色和页面行为。
- 入库前：提供3—5份公开或获授权资料并确认模型服务可处理这些资料。
- 闭环完成：核查引用页码、答案与原文支持关系。
- 评测阶段：确认至少30题证据，复核争议样例，不以 AI 生成答案直接作为标准答案。
- 汇报前：完整走一次本机演示，理解架构取舍，核对贡献与 AI 声明。

每批记录：代码与迁移、自动检查命令及真实结果、限制、人工待验事项、Git提交及下次起点。自动验证与人工验收分开；本地提交与 GitHub 推送分开。
