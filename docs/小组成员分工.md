# 知序小组学习、参与和汇报安排

系统：**知序——高校科研团队知识管理与协作平台**。课程题目：**面向高校科研团队的知识管理与协作平台：软件体系结构设计与评估**。

更新日期：2026-11-03。用户是唯一已确认的人工开发负责人，AI辅助主要技术实现；其他成员已完成的开发或评审证据尚未提供。以下六个板块是学习和汇报安排，不代表六人均已开发。旧编码分工已 [归档](history/2026-11-03-before-system-refresh/小组成员分工.md)。

## 1. 六个责任板块

| 成员占位 | 学习与汇报主责 | 应理解的当前功能 | 可以真实完成的参与任务 |
| --- | --- | --- | --- |
| 成员1 | 业务背景、总体架构与组织权限 | 教师确认、入组审批、公共库、内部项目、师生身份与管理权限 | 走通角色流程，评审权限矩阵并记录问题 |
| 成员2 | 文件、版本与异步任务 | 100MiB可配置上传、密码PDF、隔离解析、租约/重试、原子发布 | 核对公开资料原文位置，验收失败新版保留旧版 |
| 成员3 | 检索与重排序 | jieba、向量、RRF、重排、模型兼容与降级 | 阅读语料并标标准证据，核对检索结果及耗时 |
| 成员4 | 引用问答与权限复核 | 编号证据、结构/摘录检查、本人历史、版本失效和撤权 | 人工判断答案是否受证据支持，记录争议样例 |
| 成员5 | 前端与端到端体验 | 七页面、校徽、注册、通讯录、公共/项目切换及原文 | 亲自完成桌面/手机验收，记录问题和复测 |
| 成员6 | 运行、审计与质量评估 | 心跳/追踪、数据库退避、逻辑删除、检索评测及限制 | 复查测试证据，组织真实标注和实验复核 |

七个产品板块与六个汇报板块不必一一对应。成员2同时讲资料与任务，成员6同时讲评测与运行；每个人围绕职责、接口、质量属性和证据讲解。

## 2. 当前协作方式

用户负责开发决策、集成、资料许可和最终验收，AI协助实现与自动验证。其他成员不必同时在场，可以提交实际评审、标注、测试或修复记录，写明日期、步骤和证据。

若课程要求每人编码，应另行分配真实的小任务，由本人完成并保留提交及验证记录，不能事后把用户/AI已完成模块登记为其他人的开发。

| 工作 | AI与负责人可提供 | 对应成员必须实际完成 |
| --- | --- | --- |
| 架构学习 | 代码位置、接口与取舍说明 | 阅读、提问并能解释 |
| 人工验收 | 脚本及操作清单 | 亲自操作，判断预期并记录 |
| 质量标注 | 格式、工具、问题草稿 | 阅读原文并确认标准证据与语义支持 |
| 材料 | 图表与讲稿初稿 | 核查采纳内容，独立理解并亲自汇报 |

## 5. 汇报口径

- 已确认教师才能创建团队，学生不能；自行选择教师不是认证。
- 入组不授予所有内部项目权限，公共库和内部项目分别授权。
- 删除团队是逻辑删除，底层资料与审计保留，无用户恢复入口。
- 引用匹配不证明答案真实，正式人工质量评测尚未完成。
- 截至第九批106项自动回归通过，不等于人工验收通过或外部模型始终在线；最近生成检查曾返回503。
- 协作指审批、权限、通讯录和资料共享，未实现共同编辑、即时通信或完整项目进度管理。
