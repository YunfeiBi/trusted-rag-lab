日期：2026-11-03。按用户要求由AI辅助开发、自动验证及记录，待用户人工验收；教师真实身份必须由人确认。

## 本批成果

1. 七板块中的首个入口改为“团队与项目”，支持多团队切换、创建/申请、入组审批、师生通讯录和团队公共资料入口。
2. 只有已确认教师可创建团队，学生及自行选择教师但未确认的账号均被后端拒绝。提供本机可信管理员确认工具，网页不能自我授予教师权限。
3. 注册后没有团队访问权；申请批准后可访问公共库，内部项目仍需单独授权。教师/学生身份、团队角色和项目角色分别展示和判断。
4. 支持申请撤回/拒绝后重申、委派管理员、转交所有权、退出和移除；退出清除该团队下所有项目授权，并保护最后管理员。
5. 迁移0007及所有项目/检索/问答权限链已接入团队资格，保留既有项目与资料。

## 人工验收步骤

访问 http://127.0.0.1:5173 ，刷新并重新登录：

1. 学生注册或登录后不能看到创建团队表单；通过API直接创建也应拒绝。教师注册后先显示“待确认”。
2. 本机管理员核实教师真实身份，再按 [教师身份确认说明](团队权限与教师身份确认.md) 执行确认命令。重新登录后才会显示创建团队入口。不会自动把demo_admin等账号当作教师。
3. 已确认教师创建团队，向学生提供团队编号。学生在“加入团队”中提交申请，待审批时不能访问团队成员或资料。
4. 团队管理员批准申请。学生刷新团队后可看到师生与QQ邮箱、访问公共库，但看不到未授权内部项目。
5. 项目管理员添加已入组学生后，学生可访问该项目；未入组用户不能直接添加为项目成员。
6. 用专门测试成员检查退出/移除。成功后原会话不能继续访问该团队资料；若仍是最后一位项目管理员，应先交接再退出。

资料、检索、问答、评测等入口只作用于顶部当前范围；团队公共库与项目内部库分别选择，不默认跨库混合回答。
