# 第九批验收：删除团队

日期：2026-11-03。按用户要求由AI辅助实现、验证及记录，待用户人工验收。

## 删除规则和入口

团队所有者在“团队与项目”中选择团队，在团队概览点击“删除团队”。团队管理员、普通成员、未加入团队者不能执行；学生/教师身份不替代所有者权限。旧迁移团队的所有者也按实际管理关系判断，不推定教师身份。

删除前展示内部项目、资料、成员和未完成任务数量，并要求输入当前完整团队名称。前端按钮保护与后端名称验证同时生效；发生改名、所有权转交或重复删除时，后端按当前状态重新判断，不信任预览。

这是**逻辑删除**：删除后团队从工作区移除，公共库及所有内部项目停止访问，但项目、资料文件、片段、历史、评测和审计记录保留在本机。不会物理清理文件，也不会回收这些文件的磁盘空间。当前没有恢复入口，不能只修改删除标记来假定恢复了原成员授权。

## 后端行为

迁移 `0008_team_deletion` 为teams增加 `is_active` 和 `deleted_at`，不新增表，不删除或停用任何既有团队；正常升级后原团队仍有效。

- `GET /api/teams/{id}/deletion-preview` 仅所有者可查看影响计数。
- `DELETE /api/teams/{id}` 请求体为 `{"confirm_name":"完整团队名称"}`。
- 单事务按团队→项目→资料→任务顺序加锁，将团队标为已删除、撤下其资料，取消queued/processing任务和租约，关闭pending入组申请。
- 删除该团队的TeamMembership与所有Project Membership授权，保留账号和其他团队权限；记录 `team.deleted` 事件于该团队公共库审计，记录仍在数据库保留，但删除后没有面向原成员的审计网页入口。
- 团队列表、项目列表、成员、资料原文、任务、检索、问答及历史等资格判断均检查团队有效性。即使手工残留成员关系，已删除团队也不允许访问；原编号不能再申请加入。
- 本人申请历史保留并显示“团队已删除”，待审批申请自动关闭。再次调用删除返回404，不重复写入删除审计。
- 账号、教师确认资格和其他团队均不删除。已下载或已展示的内容无法从对方设备撤回；进行中的模型请求无法撤回已经发送的输入，返回结果前仍会重新验证权限。

存在已删除团队时，迁移降级会拒绝移除删除标记，避免通过降级意外重新开放团队。当前没有恢复、物理清理、保留期限自动执行或备份恢复功能。

## 人工验收

刷新 http://127.0.0.1:5173 ，以团队所有者登录，在团队概览中查看删除入口和说明。建议先用专门的测试团队体验；只有确认要关闭该团队及全部项目访问后，才输入完整名称并提交。非所有者不应出现入口，也不能绕过前端调用删除接口。

本批仅本地提交，未推送GitHub。前八批代码状态见开发台账；人工验收和真实质量评测仍需用户参与。
