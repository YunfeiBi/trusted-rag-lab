## Python

项目使用独立 Python 3.13，依赖已锁定到 `uv.lock`。Windows 上避免直接调用 PATH 中的 MSYS2 Python。

```powershell
uv sync --locked --python 'D:/apps/python/python.exe'
.\.venv\Scripts\python.exe scripts/check_environment.py
```

其他成员修改解释器路径为自己的 Python 3.13。若使用不同 Python 主次版本，需全组确认并重新验证锁文件。

## 前端

```powershell
cd frontend
npm ci
npm run dev
```

访问终端显示的本地地址。当前为七个独立业务页面；完整本机启动建议使用项目脚本。生产构建使用 `npm run build`；依赖锁定于 `package-lock.json`。

## PostgreSQL

本机 PostgreSQL 位于 `D:/apps/PostgreSQL/18`，服务运行在 `127.0.0.1:5432`。已从官方 pgvector v0.8.7 源码编译并安装扩展文件，没有修改现有数据库或认证配置。

复制 `.env.example` 为 `.env` 后填写配置；已有 `.env` 不要覆盖。

- `POSTGRES_ADMIN_PASSWORD`：安装时 postgres 管理员密码，仅用于初始化。
- `POSTGRES_PASSWORD`：独立应用账号密码，留空时初始化脚本会随机生成并保存到本地 `.env`。
- 默认数据库 `trusted_rag_lab`，应用账号 `trusted_rag_app`。

```powershell
.\.venv\Scripts\python.exe scripts/setup_database.py
```

脚本只操作 `trusted_rag` 前缀的项目角色和数据库，遇到已有不同所有者的数据库会停止，不修改其他项目。创建后启用 vector 并使用应用账号做临时表和向量距离验证。该验证成功前，不能声称数据库链路已经就绪。

pgvector 的 Windows 构建遵循官方说明：https://github.com/pgvector/pgvector 。`scripts/build-pgvector.cmd` 含本机 Visual Studio 与 PostgreSQL 路径，其他成员先修改路径，在管理员终端执行；已安装时无需重复编译。

## 模型

生成服务填写 `MODEL_BASE_URL`、`MODEL_API_KEY` 和 `CHAT_MODEL`，地址须包含供应商要求的 API 前缀（例如 `/v1`），不包含 `/chat/completions`。

向量服务可单独填写 `EMBEDDING_BASE_URL`、`EMBEDDING_API_KEY` 与 `EMBEDDING_MODEL`；前两项留空则复用生成服务配置。配置模型名称不代表该服务支持该模型，必须实际调用验证。

```powershell
.\.venv\Scripts\python.exe scripts/check_models.py
```

该脚本仅向配置的 OpenAI 兼容接口发送极短合成文本，可能产生少量调用费用，不发送项目资料，不输出凭据。

重排序使用 `.\.venv\Scripts\python.exe scripts/check_rerank.py` 验证。默认复用 Embedding 地址和密钥，也支持单独设置 `RERANK_BASE_URL` 和 `RERANK_API_KEY`。当前脚本使用硅基流动 `/rerank` 格式，不能直接当作所有供应商通用适配器。

### 向量链路复验

运行 `.\.venv\Scripts\python.exe scripts/check_embeddings.py` 可验证批量向量生成，以及实际维度的 pgvector 临时表写入和余弦距离检索。测试结束回滚，不保留测试行。最近一次相关文本余弦相似度约 0.7750，无关文本约 0.2248，仅用于基本行为检查，不代表真实资料上的检索质量评估。详细本地结果保存于 `.local/embedding-check.json`，不含密钥或向量正文。

后续建立文档片段表时，应使用当前模型实际返回的 1024 维；更换模型或维度后需重新生成相应资料向量，不能混用。

重排序复验中，权限控制片段得分约 0.999828、文档解析片段约 0.001014、午餐片段约 0.000042。这里只检查基本行为，分数不是正确率，也不代表真实资料上的总体效果。结果保存在 `.local/rerank-check.json`，该文件被 Git 忽略。模型接口已分别可用，业务中的入库、检索、权限及问答整合仍待实现。
