# 本机故障排查与恢复

适用于迁移0004及之后的本机原型。记录由AI辅助起草，操作时按真实状态判断，不要删除数据库、清空资料或覆盖 `.env`。

## 先判断故障位置

| 现象 | 检查与处理 | 预期边界 |
| --- | --- | --- |
| 浏览器打不开 | 检查启动脚本输出的5173地址及前端进程 | 不代表数据库或模型异常 |
| 登录提示数据库暂不可用 | 查看本机PostgreSQL服务是否运行，检查ready接口和后端日志 | API不自动重试写请求，保留追踪编号 |
| 资料页无近期入库心跳 | 检查Worker进程和日志，确认数据库可连接 | 心跳过期阈值90秒，长解析也可能延迟心跳 |
| 任务等待且提示自动重试时间 | 等待显示时间后由Worker领取 | 这是不早于时间，不保证精确该时刻开始 |
| processing期间进程中断 | 恢复Worker，等待显示的租约期限到期 | 原租约300秒，最多3次领取，未必立即重新开始 |
| 任务failed | 阅读错误原因；可恢复错误在管理员界面点击重试 | 只允许最新版本失败任务重试，不能恢复已撤下资料 |
| 新版失败但旧版可用 | 检查当前可用版本列 | 原子发布保证失败新版不替换旧版 |
| 引用问答提示服务不可用 | 查看仍有效的证据、追踪编号，检查模型配置及上游服务 | 不展示未经引用校验的草稿，不会自动重试生成 |
| 历史回答显示依据变化 | 检查资料是否撤下或已有新版本，重新提问 | 历史快照隐藏不等于物理删除 |

## 常用操作

在仓库根目录执行：

```powershell
# 查看进程记录（仅包含本项目PID及路径，不是账号文件）
Get-Content .local/local-processes.json

# 健康检查：live仅表示API可响应；ready核对数据库迁移
Invoke-RestMethod http://127.0.0.1:8000/api/health/live
Invoke-RestMethod http://127.0.0.1:8000/api/health/ready

# 安全重启受管项目进程，保留PostgreSQL、资料及成员关系
./scripts/stop-local.ps1
./.venv/Scripts/python.exe -m alembic upgrade head
./scripts/start-local.ps1
```

如果端口占用，先核对占用者，不直接杀掉所有Python或Node进程。启动脚本不会接管其他进程。停止脚本对记录的进程校验可执行文件与项目路径。

后台日志位于 `.local/backend.err.log`、`.local/worker.err.log`、`.local/frontend.err.log`。按界面追踪编号或task UUID关联；Worker数据库故障通常出现 `worker_database_unavailable`，恢复后出现 `worker_database_recovered`。成功入库日志含四阶段耗时，不含文档正文。

不要把 `.env`、账号密码文件或完整本地数据发到聊天、群或GitHub。提供故障反馈时只需操作步骤、错误类别和追踪编号。

## 验证命令

```powershell
./.venv/Scripts/python.exe -m pytest tests/test_reliability.py tests/test_model_clients.py -q
./.venv/Scripts/python.exe scripts/check_browser.py --runtime
```

前者在随机隔离schema中注入故障，不停止真实数据库；后者需要已启动前后端及Worker，使用本地演示账号做只读诊断和三身份登录检查。浏览器脚本默认不带上传、搜索或问答参数时，不调用外部模型。

进程强制结束后的恢复依赖重新启动Worker；当前没有Windows服务自动拉起、跨机容灾、备份恢复验证或磁盘损坏恢复。数据需独立备份，GitHub只保存已提交并推送的代码和文档。
